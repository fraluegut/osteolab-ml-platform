El problema

Miles de huesos, muy pocos especialistas

  • En una excavación salen bolsas y bolsas de restos óseos.
  • Identificarlos exige un zooarqueólogo y una colección de referencia.
  • Ese especialista es el cuello de botella: el material espera meses en el almacén.
  • Pregunta: ¿puede una foto dar una primera identificación en segundos?

Juego rápido

¿Qué hueso es este?

Fémur humano. Y fíjate en todo lo demás: cristal, reflejos, soporte, otros objetos, desenfoque. Así son las fotos reales.
Preguntar al público, que levanten la mano quien diga fémur / húmero / tibia. Luego revelar. El mensaje: el hueso es fácil para un humano; lo difícil para un modelo es todo lo que NO es hueso. Esta foto está en nuestro examen de fotos reales.

Por qué es difícil

Pocos datos, muchas clases

Primera decisión de ML — antes de escribir un modelo

No predecir hueso exacto ni especie. Predecir grupo morfológico:

cráneomandíbula/maxilarhueso largohueso plano pelvissacrovértebracostillahueso pequeño
Con 1-2 especímenes por hueso no hay nada que aprender a nivel de especie: el modelo memorizaría el espécimen. Reformular a 9 grupos por forma fue la decisión con más impacto de todo el proyecto. Más adelante bajamos de nivel, pero con otra arquitectura (cascada).

Datos sintéticos

Centrar el objeto, repartir cámaras, mirar al centro

def fibonacci_sphere(n, radius):
    """Direcciones bien repartidas en la esfera -- no
    vistas al azar, que se amontonan en los polos."""
    points = []
    phi = math.pi * (3.0 - math.sqrt(5.0))
    for i in range(n):
        y = 1 - (i / max(n - 1, 1)) * 2
        r = math.sqrt(max(0.0, 1 - y * y))
        theta = phi * i
        points.append(Vector((math.cos(theta)*r, y,
                               math.sin(theta)*r)) * radius)
    return points

def look_at_matrix(cam_location, target):
    direction = target - cam_location
    rot = direction.to_track_quat("-Z", "Y")
    mat = rot.to_matrix().to_4x4()
    mat.translation = cam_location
    return mat

# centro en espacio de MUNDO: no se mueve el objeto
# (evita mover padre+hijos del glTF dos veces)
center = Vector(all_verts_world.mean(axis=0))

for i, direction in enumerate(fibonacci_sphere(n_views, 1.0)):
    cam_location = center + direction * distance
    cam.matrix_world = look_at_matrix(cam_location, center)
  • Centro en mundo, no en el objeto: la jerarquía del glTF tiene padres e hijos; mover el objeto los desplaza dos veces.
  • Fibonacci sphere: vistas repartidas uniformemente, no un muestreo al azar que amontona cámaras en los polos.
  • Distancia por focal: 24-70mm variable → cada vista recalcula la distancia para que el hueso llene el fill objetivo del encuadre.
  • Entre vista y vista también cambia el HDRI y se reaplica la suciedad procedural: "dar vueltas" es también cambiar la escena, no solo la cámara.
Esto es render_bone_bproc.py, la versión en producción (sustituye a render_bone_lab.py de la slide anterior). look_at_matrix usa to_track_quat de mathutils: la cámara mira siempre al centro aunque la posición cambie. jitter pequeño en el target para que no todas las vistas sean perfectamente especulares entre sí.

Features clásicas

Medir la forma con NumPy

def _axis_shape_features(centerline):
    pts = np.asarray(centerline, dtype=np.float64)
    chord = np.linalg.norm(pts[-1] - pts[0])
    arc = np.sum(np.linalg.norm(np.diff(pts, axis=0), axis=1))
    tortuosity = arc / chord          # 1.0 = recto

    angles = [_signed_turning_angle(*pts[i - 1:i + 2])
              for i in range(1, len(pts) - 1)]
    total = sum(abs(a) for a in angles)
    # 1.0 = gira siempre al mismo lado (arco, costilla)
    # 0.0 = se cancela (recta con ruido)
    consistency = abs(sum(angles)) / total
    return tortuosity, total, consistency

Del contorno (OpenCV) salen medidas invariantes a escala:

elongacióncircularidadsolidezmomentos de Hu perfil de anchuraagujerostortuosidadajuste a arco

→ RandomForestClassifier: rápido, explicable, y la base del híbrido.

Costilla vs hueso largo: los dos son "alargados". La diferencia es que una se curva siempre hacia el mismo lado.

Un arqueólogo describe un hueso con palabras como "alargado", "curvo", "con agujero". Estas features son esas palabras convertidas en números. Son interpretables y funcionan con muy pocos datos, que es justo lo que le falta a la CNN.

El primer experimento, completo

Primera vez que se mete una red neuronal: resnet18 preentrenada + cabeza propia, entrenada en 2 fases desde el primer commit. A la derecha, el resultado desglosado por clase — no solo el agregado que quedó escrito en su momento.

Arquitectura: backbone congelado primero (no destrozar los pesos de ImageNet con una cabeza sin entrenar), luego descongelado a LR muy bajo.

class BoneClassifier(nn.Module):
    def __init__(self, backbone="resnet18", n_classes=9):
        self.backbone = timm.create_model(
            backbone, pretrained=True, num_classes=0)   # 512-d
        self.head = nn.Sequential(
            nn.Linear(512, 128), nn.ReLU(), nn.Dropout(0.3),
            nn.Linear(128, n_classes))

    def forward(self, image):
        return self.head(self.backbone(image))  # solo píxeles

class BoneClassifier(nn.Module):
    def __init__(self, backbone_name, num_classes):
        super().__init__()

Deep learning

Forma + textura: el modelo híbrido

class BoneClassifier(nn.Module):
    def __init__(self, backbone_name, num_classes, n_geom):
        super().__init__()
        self.backbone = timm.create_model(
            backbone_name, pretrained=True, num_classes=0)
        embed_dim = self.backbone.num_features   # 512
        self.head = nn.Sequential(
            nn.Linear(embed_dim + n_geom, 128), nn.ReLU(),
            nn.Dropout(0.3), nn.Linear(128, num_classes),
        )

    def forward(self, image, geom):
        embedding = self.backbone(image)
        return self.head(torch.cat([embedding, geom], dim=1))
  • ResNet18 preentrenada con timm, sobre el recorte segmentado.
  • Fase 1: backbone congelado, solo la cabeza.
  • Fase 2: fine-tuning completo con learning rate bajo.
  • Las features geométricas se escalan con StandardScaler antes del cat.

Evaluar sin engañarte · 1

24 vistas del mismo fémur = examen con chuleta

from sklearn.model_selection import StratifiedGroupKFold

def subject_ids(df):
    # "specimen" solo puede colisionar entre colecciones
    return (df["species"].astype(str).str.strip() + "::"
            + df["specimen"].astype(str).str.strip()).to_numpy()

def subject_holdout(df, target_col, test_size=0.2, random_state=42):
    splitter = StratifiedGroupKFold(
        n_splits=round(1 / test_size), shuffle=True,
        random_state=random_state)
    train_idx, val_idx = next(splitter.split(
        df, y=df[target_col], groups=subject_ids(df)))
    train_df, val_df = df.iloc[train_idx], df.iloc[val_idx]
    overlap = set(subject_ids(train_df)) & set(subject_ids(val_df))
    if overlap:
        raise RuntimeError(f"Fuga de sujeto: {sorted(overlap)}")
    return train_df, val_df
  • train_test_split por fila reparte vistas del mismo hueso a ambos lados.
  • Agrupa por sujeto, estratifica por clase: StratifiedGroupKFold.
  • Falla ruidosamente: un RuntimeError vale más que un aviso en un log.
  • Con tests en pytest. 4343 filas, 418 sujetos, 0 compartidos.
Aplica a cualquier dataset con varias filas por entidad: pacientes, clientes, máquinas, frames de vídeo. La clave species::specimen salió de un bug real: dos colecciones numeraban igual.

Optimizar es una opción. Reformular, medir mejor, revisar imágenes y conseguir el dato que falta suelen ser decisiones más valiosas.

Esta es la idea central de la charla. Un experimento no responde solo “¿subió el número?”; también dice dónde está el cuello de botella. Las cuatro flechas son decisiones reales de OsteoLab que ya hemos visto: fotos reales, Grounded-SAM, priorizar hueso plano y no celebrar dos imágenes de diferencia en un test pequeño.

Para llevarse

Cinco lecciones que no dependen de los huesos

  1. Diagnostica el cuello de botella antes de optimizar el modelo.
  2. Sintético para arrancar, real para llegar. Unas pocas fotos reales valen oro.
  3. Separa por sujeto, nunca por fila. Y que falle con excepción.
  4. Balanced accuracy, varias semillas y test pareado antes de celebrar.
  5. Mira tus datos. Visores y apps de revisión baratas encuentran lo que los tests no ven.
Cerrar volviendo a la foto del principio: el modelo la clasifica bien, y ahora sabemos cuánto nos podemos fiar de ese "bien".
